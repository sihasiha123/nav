# 20260819 导航避障奖励函数 V3 方案

## 1. 设计方式

V3 使用“稠密引导 + 稀疏终止”的混合奖励。

- 稠密奖励负责告诉无人机每一步应该如何运动。
- 稀疏奖励负责判断一次任务最终成功还是失败。

纯稀疏奖励很难开始学习，纯稠密奖励又容易让策略只追求局部奖励而不完成任务。

## 2. 总奖励

```text
总奖励 =
    目标进展
  + 静态障碍风险
  + 动态障碍风险
  + 时间成本
  + 终止奖励
```

初始形式：

```text
r_t =
    0.30 * distance_progress
  - dt * 2.0 * static_risk
  - dt * 3.0 * dynamic_risk
  - dt * 0.02
  + terminal_reward
```

## 3. 稠密奖励

### 3.1 目标进展

```text
distance_progress = previous_distance - current_distance
```

- 接近目标时为正奖励。
- 远离目标时为负奖励。
- 前进和后退使用对称尺度，防止来回运动刷奖励。
- 单步距离变化裁剪到 `[-0.1, 0.1] m`，防止异常尖峰。

### 3.2 静态障碍风险

静态风险根据 LiDAR 计算。

- 正在靠近障碍物时增加惩罚。
- 障碍物越近、预计碰撞时间越短，惩罚越大。
- 侧面或后方障碍只保留较弱的距离惩罚，避免无人机因为附近存在障碍而悬停。

初始最大惩罚约为：

```text
-2.0 / s
```

### 3.3 动态障碍风险

动态风险根据无人机与障碍物的相对位置和相对速度计算。

- 动态障碍正在接近无人机时增加惩罚。
- 使用 TTC 判断碰撞风险。
- 多个动态障碍中使用最高风险，不取平均。

初始最大惩罚约为：

```text
-3.0 / s
```

### 3.4 时间成本

```text
-0.02 / s
```

时间成本只用于避免长时间悬停，不能大到迫使无人机直接冲向目标。

## 4. 稀疏终止奖励

| 终止结果 | 奖励 |
|---|---:|
| 成功 | `+30` |
| 碰撞 | `-25` |
| 越界 | `-25` |
| 超时 | `-8` |

同一步出现多个终止条件时只计算一个，优先级为：

```text
collision > out_of_bounds > success > time_out
```

## 5. 第一版不加入的奖励

```text
goal_velocity
生存奖励
高度软约束
动作平滑
姿态惩罚
持续到达奖励
```

先确认基础导航和避障可以学习，再根据实际问题增加其他奖励项。

## 6. 实现要求

- 每个奖励项拆成独立的 Manager reward term。
- 连续风险和时间成本按 `/s` 定义。
- 距离进展和终止事件在函数中除以 `step_dt`，抵消 RewardManager 的 `dt` 缩放。
- 各奖励项分别写入日志，能够看到每个 episode 的实际贡献。
- 实现前先确认 LiDAR 的排列和方向正确。

## 7. 验证顺序

1. 无障碍场景验证是否能够到达目标。
2. 加入少量静态障碍验证静态避障。
3. 增加静态障碍数量。
4. 最后逐步加入动态障碍。

如果碰撞率下降但超时率明显上升，说明避障惩罚过强或缺少方向性；如果进展奖励很高但仍频繁碰撞，说明风险信号太晚或太弱。

## 8. `ppo_20260819_222322` 训练结果

### 8.1 运行信息

- W&B run：`pg3cpgt1`
- 并行环境：`1024`
- 训练迭代：`2000`
- `physics_dt=1/60`，`decimation=1`
- Episode 时长：`60 s`
- 已生成：`checkpoint_final.pt`

这次运行使用的是现有的单项 `navigation_reward`（之前移植的 UAV 权重），并不是本文件前面规划的 V3 奖励函数。

### 8.2 终止统计

| 训练阶段 | Done 数量 | 成功率 | 静态碰撞 | 动态碰撞 | 总碰撞 | 越界 | 超时 | Done Return |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Iteration 1-500 | 11196 | 22.4% | 23.4% | 31.3% | 54.7% | 11.8% | 11.0% | -10.80 |
| Iteration 1501-2000 | 13151 | 68.0% | 14.7% | 13.5% | 28.2% | 3.1% | 0.7% | +15.94 |
| Iteration 1801-2000 | 4817 | 67.5% | 15.0% | 13.9% | 28.9% | 1.7% | 1.9% | +14.92 |
| 全部训练 | 51332 | 59.6% | 15.2% | 18.2% | 33.4% | 4.4% | 2.6% | +10.45 |

训练早期主要是碰撞和越界，后期成功率稳定在约 67% 至 72%。Iteration 801-900 的成功率最高约为 79.1%，但后续仍有波动，因此不能仅依据最高窗口判断已经收敛。

### 8.3 训练结论

这次训练已经学会基本的目标导航：

- 越界率由 11.8% 降至 3.1%。
- 超时率由 11.0% 降至不足 1%。
- 动态碰撞率由 31.3% 降至 13.5%。
- 静态碰撞率由 23.4% 降至 14.7%。

当前主要问题已经从“不会飞到目标”变为“到达目标过程中仍然会撞障碍物”。因此，这次结果可以作为新的导航 baseline，但还不是满足安全要求的最终策略。

### 8.4 奖励尺度分析

Isaac Lab Manager 会将奖励乘以 `step_dt=1/60`。因此原始终止奖励的实际单次贡献约为：

```text
collision       -120 * 1/60 = -2.0
out_of_bounds   -120 * 1/60 = -2.0
goal_first       +50  * 1/60 = +0.833
```

后 200 个 iteration 中，已经按 `dt` 缩放的平均每步奖励为：

| 奖励项 | 平均值 |
|---|---:|
| `goal_velocity` | +0.01285 |
| `progress` | +0.00173 |
| `static_avoidance` | -0.00248 |
| `dynamic_avoidance` | -0.00087 |
| `height` | -0.00034 |
| `collision` | -0.00043 |
| `out_of_bounds` | -0.00003 |
| `total` | +0.01063 |

当前正向奖励主要来自朝目标方向的速度，距离进展奖励次之。碰撞事件的分项均值会被整个 rollout 的并行环境和时间步稀释，不能把 `collision_mean` 直接理解为单次碰撞惩罚。

### 8.5 PPO 状态

- 训练正常结束，没有 NaN 或崩溃。
- Critic loss 从早期平均约 `0.0745` 降到后期约 `0.0141`。
- Actor 和 Critic 梯度范数均下降，数值处于正常范围。
- 成功率后期仍在 64% 至 73% 间波动，说明策略已形成但尚未完全稳定。

### 8.6 实验复现注意事项

这次运行时间上与“`+Y` 边起点到 `-Y` 边目标”的固定方向 reset 修改一致，但该修改当时尚未提交，且 W&B config 没有记录 `reset_mode`、起点边和目标边。因此该实验的场景配置不能只依靠 W&B 完全复现，后续应将这些字段显式写入 run config。

### 8.7 后续验证

在继续修改奖励函数前，先使用确定性策略评估以下 checkpoint：

```text
checkpoint_800.pt
checkpoint_900.pt
checkpoint_1600.pt
checkpoint_2000.pt
```

每个 checkpoint 至少运行 200 至 500 个 episode，分别统计成功率、静态碰撞率、动态碰撞率、越界率和平均到达时间。确认最优 checkpoint 后，再针对碰撞率进行单变量奖励调参。
