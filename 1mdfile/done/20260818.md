> 状态说明：本文只记录 2026-08-18 实际运行过的奖励函数 V2 及其结果。V2 因碰撞率明显恶化已经撤销，当前代码已恢复为之前的单一 `navigation_reward()`。

## 1. 昨天为什么修改奖励函数

此前三个 run 暴露出两种退化策略：

| run | 最后 200 iteration 成功率 | 碰撞率 | 越界率 | 超时率 | 主要问题 |
|---|---:|---:|---:|---:|---|
| `ppo_20260816_190814` | 24.21% | 24.86% | 42.48% | 8.86% | 利用高度越界快速结束 |
| `ppo_20260818_204907` | 15.39% | 32.23% | 2.59% | 49.79% | 越界受控，但大量慢速生存 |
| `ppo_20260818_211713` | 14.32% | 21.24% | 0.79% | 63.69% | episode 延长到 60 s 后更倾向悬停和超时 |

旧奖励把进展、速度、避障和终止事件全部写在一个函数中。Isaac Lab `RewardManager` 会把函数输出统一乘以 `step_dt`，这会导致单步距离变化和一次性终止奖励也被缩小，而连续速度奖励相对占主导。昨天的 V2 修改主要想解决两个问题：

1. 将奖励拆成独立 Manager term，统一连续 rate 和一次性 event 的时间语义。
2. 让到达、碰撞、越界和超时的结果差异足够明显，并可分项统计调参。

## 2. 昨天实际运行的 V2 奖励

训练目录：

```text
runs/ppo_20260818_225534
wandb/offline-run-20260818_225613-ur60wrw7
```

训练设置：

```text
num_envs = 1024
episode_length_s = 60
training_frame_num = 32
max_iterations = 2000
```

V2 将奖励拆成 8 个 Manager term：

```text
progress
static_risk
dynamic_risk
time
success
collision
out_of_bounds
time_out
```

### 2.1 进展奖励

只使用无人机到目标的水平距离变化：

```text
delta_distance = previous_distance_xy - current_distance_xy
delta_distance clamp = [-0.10 m, 0.10 m]
shaped_progress = positive_progress - 0.20 * negative_progress
Manager weight = +0.5
```

PPO 实际获得：

```text
前进 1 m：+0.5
后退 1 m：-0.1
```

函数内部除以 `step_dt`，抵消 Manager 对单步距离变化再次乘 `dt` 的影响。

### 2.2 连续风险和时间成本

```text
static_risk:
  safe_distance = 1.2 m
  normalized squared proximity
  weight = -0.3 / s

dynamic_risk:
  safe_distance = 1.5 m
  nearest visible dynamic obstacle surface clearance
  weight = -0.5 / s

time:
  weight = -0.03 / s
```

昨天实际运行的动态风险只用了距离，没有实现相对速度和 TTC。

### 2.3 终止事件

```text
success       +30
collision     -20
out_of_bounds -20
time_out       -8
```

事件函数内部同样除以 `step_dt`，所以 Manager 乘完 `dt` 后，PPO 收到的是上面的完整事件值。终止结果采用互斥优先级：

```text
collision > out_of_bounds > success > time_out
```

V2 删除了重复的 `goal_velocity`，也暂时没有加入高度软约束、动作平滑、`goal_first` 和 `goal_reached`。

## 3. V2 实验结果

### 3.1 终止结果

| 统计区间 | done 数量 | 成功率 | 静态碰撞 | 动态碰撞 | 总碰撞率 | 越界率 | 超时率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 全部 2000 iter | 47,675 | 1.05% | 63.27% | 19.06% | 82.32% | 3.59% | 13.06% |
| 最后 500 iter | 13,902 | 2.13% | 68.57% | 15.73% | 84.30% | 3.14% | 10.44% |
| 最后 200 iter | 5,303 | 1.57% | 66.81% | 15.92% | 82.73% | 4.09% | 11.65% |

最后 200 iteration 的加权 episode return 为 `-11.5812`，rollout 单步平均奖励约为 `-0.00925`。训练后期成功率没有持续上升，总碰撞率保持在 80% 以上，因此这次训练没有收敛到可用的导航策略。

### 3.2 最后 200 iteration 的实际奖励构成

W&B 的 `Episode_Reward/<term>` 会除以最大 episode 秒数 60。将它乘回 60 后，可以得到每个已结束 episode 的平均实际贡献：

| 奖励项 | 平均贡献 |
|---|---:|
| progress | `+7.6964` |
| static_risk | `-0.5525` |
| dynamic_risk | `-0.3159` |
| time | `-0.5903` |
| success | `+0.4695` |
| collision | `-16.5454` |
| out_of_bounds | `-0.8109` |
| time_out | `-0.9323` |
| 合计 | `-11.5812` |

这个分解说明：策略在碰撞前平均仍能通过接近目标累计约 `+7.70`，而静态和动态连续风险合计只有约 `-0.87`。也就是说，V2 给出的学习信号更接近“尽量向目标前进，最后碰撞”，而不是“提前绕开障碍物再前进”。

## 4. 对 V2 失败原因的判断

### 4.1 风险信号太晚且太弱

静态风险只在 1.2 m 内明显生效，动态风险只看当前距离。无人机已经进入危险区域时，留给策略改变速度和方向的时间很短。相比 `+7.70` 的平均进展收益，`-0.87` 的连续避障成本不足以改变动作选择。

但不能只把全局最小距离惩罚继续放大。在障碍密集场景中，无人机即使沿安全方向移动，也可能长期靠近侧面或后方障碍；过强的无方向距离惩罚会再次把策略推向悬停和超时。

### 4.2 LiDAR 张量的空间排列需要先修正

当前 LiDAR pattern 是 4 条竖直射线乘 36 个水平角。pattern 产生的射线顺序是先遍历一个竖直角下的 36 个水平角，再进入下一个竖直角。

当前观测直接：

```python
reshape(num_envs, 1, 36, 4)
```

这会把相邻水平角和竖直层交错到 CNN 的二维邻接关系中。正确保留“水平 36、竖直 4”的排列应类似：

```python
lidar.reshape(num_envs, 4, 36).transpose(1, 2).unsqueeze(1).contiguous()
```

最小距离类奖励和碰撞判定不受这个 reshape 影响，但 CNN 学习“障碍物在哪个方向”会受影响。`/home/robot/RL/uav` 当前 direct 版本采用了与 nav 相同的直接 reshape，因此它只能说明代码来源一致，不能证明这个排列正确。

此外，LiDAR 是无人机 yaw/body 对齐的坐标，而导航状态、动态障碍观测和动作主要使用目标坐标系。网络需要同时理解两套方向表达，这会增加学习难度。

### 4.3 PPO 的时间尺度太短

当前物理与控制步长约为：

```text
sim.dt = 1/60 s
decimation = 1
rollout = 32 steps = 0.533 s
gamma = 0.99
lambda = 0.95
```

`gamma=0.99` 在 60 Hz 下的折扣半衰期约 1.15 s；`gamma * lambda` 对 GAE 的有效时间范围更短。完整路径可能需要二十多秒，而避障动作的好坏也常在数秒后才体现。终止碰撞惩罚虽然数值大，但难以稳定归因到较早的动作。

### 4.4 场景从一开始就过难且样本相关

完整场景包含约 200 个静态障碍和 100 个动态障碍，1024 个无人机共享同一片地形及障碍运动逻辑。对尚未掌握基础到达和静态绕障的策略而言，直接训练完整任务会同时混入导航、静态避障、动态预测和坐标表达问题；大量并行环境也不等于同等数量的独立场景。

## 5. V2 实验结论

V2 的“拆分奖励项、修正 Manager `dt` 语义、互斥终止事件”方向是正确的，但具体避障信号仍然只是进入危险距离后的惩罚。实验表明，单纯依赖最小距离风险不能形成可靠的导航避障策略。

本次 run 保留的主要经验是：

- 进展收益相对风险成本过高，策略可以在碰撞前获得大量正回报。
- 风险触发过晚，没有为策略预留足够的制动或转向时间。
- 不能只继续放大无方向的距离惩罚，否则容易从“前进后碰撞”转变为“悬停后超时”。
- LiDAR 方向输入、PPO 时间尺度和场景难度需要在下一轮奖励修改前一起验证。
