# 2026-08-16 extras 日志链路调整方案

## 1. 目标

训练日志分成两类来源：

```text
extras["log"]  环境 / episode 指标
train_info     PPO / optimizer 指标
```

环境相关统计不再由 trainer 自己重复计算 episode return/length，而是读取
Manager 已经计算好的 termination term mask，并按 rollout 聚合所有 done
环境。这样 success、collision、out_of_bounds、time_out 的定义只维护在环境
侧，trainer 不复制终止逻辑。

## 2. 当前问题

旧版 `scripts/train.py` 里有 `EpisodeStatistics`：

```text
Episode/return
Episode/length
Episode/count
Episode/truncated_rate
```

这些是 trainer 根据 reward、terminated、truncated 重新算出来的 episode
统计。并行训练时更需要关注当前 rollout 里所有 done 环境的结果，而不是只看
某一次 reset 返回的 episode extras。

这样会产生两套口径：

- Manager 环境本身已经会在 reset 时写 `extras["log"]`；
- trainer 又自己维护一份 episode 统计。

后续如果 success、collision 或 timeout 的定义变动，容易出现 env 和 trainer
统计不一致。

## 3. Manager extras 的限制

Manager 环境在 done env reset 时会调用各个 manager 的 `reset()`，并把它们
返回的信息写入：

```python
extras["log"]
```

当前 nav 任务里主要会出现：

```text
Episode_Reward/navigation

Episode_Termination/static_collision
Episode_Termination/dynamic_collision
Episode_Termination/out_of_bounds
Episode_Termination/success
Episode_Termination/time_out
```

这些就是环境侧 episode 指标的权威来源。

但这些 `Episode_*` 指标表示最近一次 reset 的 manager 统计，不等价于当前
rollout 中所有 done 环境的汇总。对于 1024 并行环境，trainer 输出应按
`training_frame_num` 这一段 rollout 聚合 done 原因。

## 4. 新链路

rollout 收集时读取 env.step 返回的 done 标志：

```python
next_obs, reward, terminated, truncated, _ = env.step(action)
```

然后从 `env.unwrapped.termination_manager` 读取每个 termination term 的 mask：

```python
done = terminated | truncated
for term_name in termination_manager.active_terms:
    term_done = termination_manager.get_term(term_name)
```

统计口径：

```text
Rollout_Done/count

Rollout_Reward/done_return_mean
Rollout_Reward/done_return_min
Rollout_Reward/done_return_max

Rollout_Termination/static_collision_count
Rollout_Termination/static_collision_rate
Rollout_Termination/dynamic_collision_count
Rollout_Termination/dynamic_collision_rate
Rollout_Termination/out_of_bounds_count
Rollout_Termination/out_of_bounds_rate
Rollout_Termination/success_count
Rollout_Termination/success_rate
Rollout_Termination/time_out_count
Rollout_Termination/time_out_rate
```

这些 rate 的分母是当前 rollout 内所有 done 环境数量。

`done_return_*` 是当前 rollout 内所有完成 episode 的累计回报。由于 episode
可能跨越多个 iteration，trainer 需要维护每个并行 env 的当前 episode return
buffer；某个 env done 后，把它的累计回报加入本次 rollout 统计并清零。

训练循环里：

```python
rollout, obs_td, env_log = collect_ppo_rollout(...)
train_info = agent.update(rollout)
```

环境指标直接记录：

```python
if env_log:
    wandb_run.log(env_log, step=iteration + 1)
```

算法指标单独记录：

```text
Rollout/reward_mean
Loss/actor
Loss/critic
Policy/entropy
GradNorm/actor
GradNorm/critic
```

终端输出只保留核心指标，避免被详细 count/rate 淹没：

```text
[TRAIN] iteration=...
  rollout
    done_count
    done_return_mean
    step_reward_mean
  result
    success_rate
    collision_rate
    out_of_bounds_rate
    time_out_rate
  loss
    actor
    critic
    entropy
  grad
    actor
    critic
```

完整细分指标仍写入 wandb：

```text
Rollout_Termination/static_collision_count
Rollout_Termination/static_collision_rate
Rollout_Termination/dynamic_collision_count
Rollout_Termination/dynamic_collision_rate
Rollout_Result/collision_count
Rollout_Result/collision_rate
Rollout_Reward/done_return_min
Rollout_Reward/done_return_max
```

## 5. 本次代码修改

- 删除 `EpisodeStatistics`。
- 新增 `RolloutEnvStatistics`，累计当前 rollout 内所有 done 环境的终止原因。
- 新增 `EpisodeReturnTracker`，跨 rollout 维护每个并行环境当前 episode 的累计回报。
- `collect_ppo_rollout()` 返回 rollout 级 env log。
- 终端使用精简日志；wandb 记录完整 env/algo 指标。
- trainer 不再自己计算 `Episode/return`、`Episode/length`、`Episode/count`、
  `Episode/truncated_rate`。
- rollout 环境指标和 PPO 指标分开打印、分开写入 wandb。

## 6. 后续可选项

如果希望日志名和旧 Direct `uav` 保持一致，可以后续在环境侧额外提供别名：

```text
Episode/success
Episode/collision
Episode/out_of_bounds
Episode/time_out
```

但第一版先使用 `Rollout_Termination/...`，保证并行 rollout 的统计口径正确。
