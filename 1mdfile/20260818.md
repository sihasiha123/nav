# 20260818 导航避障奖励函数 V2 方案

## 1. 背景结论

目前三个训练结果说明，主要问题不是 PPO 网络或奖励绝对值太小，而是奖励项之间的相对尺度和语义不一致。

- `ppo_20260816_190814` 没有显式越界惩罚，最后 200 轮高度越界率约 42.48%，成功率约 24.21%。
- `ppo_20260818_204907` 增加显式越界惩罚后，高度越界率降至约 2.59%，但成功率降至约 15.39%，超时率升至约 49.79%。
- `ppo_20260818_211713` 将 episode 从 35 s 延长到 60 s 后，成功率约 14.32%，超时率约 63.69%，策略进一步转向慢速生存。

当前有效前进速度约从 1.25 m/s 降至 0.66 m/s，再降至 0.31 m/s。延长 episode 没有解决导航问题，说明策略缺少尽快到达目标的明确动力。

当前 `navigation_reward()` 同时包含连续 rate、单步状态变化和一次性终止奖励。Isaac Lab RewardManager 会统一乘以 `step_dt=1/60`，导致：

- `progress` 已经是单步距离变化，又被多乘一次 `dt`。
- 成功、碰撞和越界等一次性奖励被缩小 60 倍。
- `goal_velocity` 成为主要正奖励，但它与 `progress` 重复。
- 成功 return 和失败 return 没有形成足够清晰的差距。

## 2. 设计目标

奖励函数围绕以下顺序设计：

1. 安全到达目标是首要目标。
2. 距离进展提供主要稠密训练信号。
3. 静态、动态障碍和高度项只在出现风险时施加约束。
4. 时间成本和超时惩罚防止慢速生存。
5. 一次 episode 只计算一种终止结果，避免重复奖惩。
6. 每个奖励项独立配置和记录，支持后续调参。

奖励设计不追求单纯放大 return，而是保证：

```text
success_return
    > timeout_return
    > collision_return / out_of_bounds_return
```

## 3. PPO 实际单步奖励

以 RewardManager 处理后、PPO 实际收到的奖励为准：

```text
R_step =
    + 0.6 * positive_progress
    - 0.1 * negative_progress
    - dt * 2.0 * static_risk
    - dt * 3.0 * dynamic_risk
    - dt * 0.5 * height_risk
    - dt * 0.03
    + 25.0 * success
    - 15.0 * collision
    - 15.0 * out_of_bounds
    - 10.0 * time_out
```

第一版暂时不加入 `goal_velocity` 和 `smoothness`，避免重复目标和多余变量干扰基础奖励验证。

### 3.1 距离进展

使用水平距离，不使用三维距离作为主要导航进展：

```python
distance_xy = torch.linalg.norm(target_pos[:, :2] - drone_pos[:, :2], dim=-1, keepdim=True)
delta_distance = previous_distance_xy - distance_xy

positive_progress = torch.relu(delta_distance)
negative_progress = torch.relu(-delta_distance)
```

将 `delta_distance` 裁剪到约 `[-0.05, 0.05] m`，防止物理异常、状态写入或重置产生奖励尖峰。

选择非对称权重：

- 接近目标：`+0.6 * delta_distance`。
- 远离目标：`-0.1 * abs(delta_distance)`。

这样允许无人机为了绕开障碍物短暂远离目标，但不允许长期反向飞行。

完整 44 m 路径最多产生约 `0.6 * 44 = 26.4` 的正向进展奖励。

### 3.2 静态障碍风险

使用 LiDAR 的最小实际 clearance，并将风险归一化到 `[0, 1]`：

```python
static_risk = (
    torch.relu(static_safe_distance - static_clearance)
    / static_safe_distance
).pow(2).clamp(max=1.0)
```

初始配置：

```text
static_safe_distance = 1.2 m
static_weight = -2.0
```

只有进入安全距离后才产生惩罚。第一版不继续增大静态避障权重，因为三个 run 表明过强的安全压力可能使策略停在障碍物前。

### 3.3 动态障碍风险

动态障碍优先使用最近障碍物的预测碰撞风险，而不是对最近 5 个障碍物的惩罚简单取平均。

建议计算相对接近速度和 TTC：

```text
closing_speed = max(dot(relative_velocity, line_of_sight), 0)
ttc = clearance / max(closing_speed, epsilon)
```

TTC 风险：

```python
dynamic_risk = (
    torch.relu(safe_ttc - ttc) / safe_ttc
).pow(2).clamp(max=1.0)
```

初始配置：

```text
safe_ttc = 2.5 s
dynamic_weight = -3.0
```

障碍物没有接近速度时，退化为基于最近动态 clearance 的距离风险。

### 3.4 高度风险

使用起点和目标高度中间值作为参考高度：

```text
z_ref = (height_min + height_max) / 2
free_height_error = 0.4 m
height_error_scale = 0.6 m
```

允许在参考高度上下 0.4 m 内自由调整：

```python
height_risk = (
    torch.relu(torch.abs(drone_z - z_ref) - 0.4) / 0.6
).pow(2).clamp(max=1.0)
```

初始权重为 `-0.5`。硬边界继续保持 `z < 0.2` 或 `z > 4.0` 时终止。

### 3.5 时间与终止奖励

连续时间成本：

```text
-0.03 / s
```

60 s episode 的最大累计时间成本为 `-1.8`，用于提供持续但不过强的到达压力。

一次性终止奖励：

| 结果 | PPO 实际奖励 |
|---|---:|
| 安全成功 | `+25` |
| 静态或动态碰撞 | `-15` |
| 高度越界 | `-15` |
| 超时 | `-10` |

终止结果必须互斥，建议优先级：

```text
collision
  -> out_of_bounds
  -> safe_success
  -> time_out
```

如果到达目标时同时发生碰撞，则按碰撞处理，不发放成功奖励。

## 4. Isaac Lab Manager 的 dt 处理

RewardManager 会执行：

```python
value = reward_func(env) * weight * env.step_dt
```

因此连续风险项可以直接返回 rate，而距离变化和一次性事件需要除以 `step_dt`。

距离进展函数应返回：

```python
progress_rate = (
    0.6 * positive_progress
    - 0.1 * negative_progress
) / env.step_dt
```

终止事件函数应返回：

```python
success_rate = success.float() / env.step_dt
collision_rate = collision.float() / env.step_dt
out_of_bounds_rate = out_of_bounds.float() / env.step_dt
time_out_rate = time_out.float() / env.step_dt
```

对应的 `RewTerm.weight` 分别配置为 `25`、`-15`、`-15` 和 `-10`。Manager 乘完 `dt` 后，PPO 才会收到预期的一次性奖励。

## 5. Manager RewardsCfg 结构

删除单一的：

```python
navigation = RewTerm(func=mdp.navigation_reward, weight=1.0)
```

拆分成以下独立项：

```python
progress
static_avoidance
dynamic_avoidance
height
time
success
collision
out_of_bounds
time_out
```

拆分后的优势：

- RewardManager 可以分别累计 episode reward。
- 默认 `extras["log"]` 可以输出各 Manager reward term。
- trainer 可以分别统计 rollout reward component。
- 后续只修改单项权重即可完成对照实验。

## 6. 代码改动范围

### `mdp/rewards.py`

- 删除或停用合并式 `navigation_reward()`。
- 新增独立奖励函数。
- 连续项返回 rate。
- progress 和终止项显式除以 `env.step_dt`。
- 终止奖励直接读取已经计算完成的 `termination_manager` term，避免重复计算碰撞。

### `mdp/events.py`

- 将历史距离改为 `previous_distance_xy`。
- reset 时初始化水平距离。
- 删除第一版不再需要的 `reached_goal_once`。
- 暂时保留 `previous_drone_vel_w`，但不参与 V2 奖励，后续确认不需要再清理。

### `nav_env_cfg.py`

- 将 `RewardsCfg` 拆成多个 `RewTerm`。
- episode 暂时保持 60 s。
- 不修改动作范围、场景障碍数量和观测结构。

### `scripts/train.py`

- 保留 rollout 维度的成功、碰撞、越界和超时统计。
- 增加按终止类型分类的 episode return。
- 增加成功时间、超时剩余距离和平均有效进展速度。

第一轮奖励验证期间不修改 PPO 网络和超参数。

## 8. 实现验证

正式训练前完成以下检查：

1. 16 个环境运行 100 iterations 的 smoke test。
2. 每一步所有 reward component 之和等于 `env.step()` 返回的 reward。
3. 单独触发成功时，PPO 实际收到约 `+25` 的终止奖励。
4. 单独触发碰撞时，实际收到约 `-15`。
5. 单独触发越界时，实际收到约 `-15`。
6. 单独触发超时时，实际收到约 `-10`。
7. 同时触发多个终止条件时，只应用一个终止奖励。
8. reset 后第一步不存在 progress 奖励尖峰。
9. 所有奖励、advantage、return、loss 和梯度均为有限值。

## 9. 训练实验设计

环境暂时使用：

```text
num_envs = 1024
episode_length_s = 60
training_frame_num = 32
max_iterations = 2000
```

固定随机种子，依次运行：

```text
seed = 42
seed = 43
seed = 44
```

W&B 配置中需要增加：

- seed。
- git commit。
- reward 权重。
- episode 时长。
- PPO 超参数。

三个 seed 趋势一致后再判断奖励是否有效，避免把单次随机初始化的结果误认为奖励改动效果。

## 10. 调参顺序

每轮只调整一类参数：

1. 检查 success、collision、out_of_bounds、time_out 的终止奖励排序。
2. 调整 progress 和时间成本，解决慢速生存。
3. 调整静态避障，平衡碰撞和停滞。
4. 调整动态 TTC 风险。
5. 调整高度软约束。
6. 策略能够稳定到达后，再考虑加入动作平滑惩罚。

判断规则：

- 超时率高且超时时距离目标很远：加强 progress、success 或时间压力，不继续延长 episode。
- 超时率高但超时时已接近目标：适当延长时间或降低最后阶段避障压力。
- 碰撞率高：先提高终止碰撞惩罚，再小幅调整连续避障权重。
- 碰撞率下降但超时率上升：避障压力过大，策略可能停止前进。
- 越界率重新上升：调整高度软约束或越界终止奖励。
- 成功率稳定后仍有明显抖动：最后加入基于动作变化的 smoothness。

## 11. 初始验收目标

Reward V2 的第一阶段目标：

```text
success_rate > 30%
out_of_bounds_rate < 5%
collision_rate < 25%
time_out_rate 持续下降
success_return 明显高于所有失败 return
```

满足第一阶段目标后，再考虑距离课程、障碍密度课程和 episode 时长课程。
