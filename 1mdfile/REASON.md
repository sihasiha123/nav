## ppo_20260816_190814

### 实验定位

这次训练是增加显式高度越界惩罚之前的基线实验，用于确认初始奖励函数是否能够学习导航，以及分析主要失败原因。它不能用于验证后续加入的 `out_of_bounds = -120` 显式惩罚是否有效。

### 训练配置

- 运行时间：2026-08-16 19:08:53 至 19:26:52，正常完成。
- 并行环境数：1024。
- Rollout 长度：每个 iteration 采集 32 step。
- 训练轮数：2000 iterations，共采集约 65,536,000 个环境 step。
- 仿真步长：`dt = 1/60 s`，`decimation = 1`。
- Episode 最大时长：35 s。
- 动作范围：三个方向均为 `[-2, 2] m/s`，没有单独限制 z 方向动作。

当时已经包含高度软惩罚，以及 `z < 0.2` 或 `z > 4.0` 的 `out_of_bounds` 终止条件；但越界时没有额外的显式 reward 惩罚。

### 训练结果

最后 200 个 iterations 的平均结果：

- 成功率：约 24.21%。
- 总碰撞率：约 24.86%。
- 静态碰撞率：约 17.62%。
- 动态碰撞率：约 7.24%。
- 高度越界率：约 42.48%。
- 超时率：约 8.86%。
- 已完成 episode 的 return 均值：约 7.35。

表现较好的窗口为 iteration 1870 至 1919，其成功率约为 26.54%，高度越界率约为 41.07%，总碰撞率约为 23.87%，episode return 均值约为 7.93。

### 结论

策略已经学习到一定的目标导航能力，但成功率最终停留在约 24% 至 27%。高度越界约占全部结束环境的 42%，是这次训练最主要的失败原因，因此后续版本增加了显式 `out_of_bounds` 惩罚。

这次运行中的 `Reward_Component/*` 使用的是未乘 `step_dt` 的 raw reward 尺度，而 PPO 实际接收的 reward 会由 Isaac Lab RewardManager 乘以 `1/60`。因此奖励分项的趋势可以直接参考，但其绝对值需要除以 60 后才能与 `Rollout_Reward/step_mean` 对比。

## ppo_20260818_204907

### 实验定位

这次训练用于验证显式高度越界惩罚。相较 `ppo_20260816_190814`，奖励中增加了 `out_of_bounds = -120`，当无人机高度满足 `z < 0.2` 或 `z > 4.0` 时，在终止回合的同时施加显式惩罚。没有增加 z 方向动作限制。

这次运行的 `Reward_Component/*` 已经乘以 `step_dt = 1/60`，与 PPO 实际收到的 `env.step()` reward 使用同一尺度，不需要再除以 60。

### 训练配置

- 运行时间：2026-08-18 20:49:48 至 21:07:01，正常完成。
- 并行环境数：1024。
- Rollout 长度：每个 iteration 采集 32 step。
- 训练轮数：2000 iterations，共采集约 65,536,000 个环境 step。
- 仿真步长：`dt = 1/60 s`，`decimation = 1`。
- Episode 最大时长：35 s。
- 动作范围：三个方向均为 `[-2, 2] m/s`，没有单独限制 z 方向动作。

### 训练结果

以下比例按照最后 200 个 iterations 中所有 done 环境的总计数加权计算。该区间共有 4055 个 episode 结束，平均每个 iteration 结束 20.28 个 episode。

- 成功率：约 15.39%。
- 总碰撞率：约 32.23%。
- 静态碰撞率：约 23.65%。
- 动态碰撞率：约 8.61%。
- 高度越界率：约 2.59%。
- 超时率：约 49.79%。
- 已完成 episode 的 return 均值：约 4.92。
- 每 step 总 reward 均值：约 0.003048。

成功率最高的连续 50 个 iterations 为 1810 至 1859。该窗口共有 1031 个 episode 结束，成功率约 17.65%，高度越界率约 2.52%，总碰撞率约 33.66%，超时率约 46.17%，episode return 均值约 5.18。

最后 200 个 iterations 的主要 reward 分项均值：

- `progress`：约 0.000728。
- `goal_velocity`：约 0.005492。
- `static_avoidance`：约 -0.001641。
- `dynamic_avoidance`：约 -0.000673。
- `height`：约 -0.000272。
- `smoothness`：约 -0.000068。
- `collision`：约 -0.000399。
- `out_of_bounds`：约 -0.000032。
- `goal_first + goal_reached`：约 0.000080。
- `total`：约 0.003048，与 `Rollout_Reward/step_mean` 对齐。

### 与基线对比

相较 `ppo_20260816_190814` 最后 200 个 iterations：

- 高度越界率从约 42.48% 降至 2.59%，显式越界惩罚有效。
- 成功率从约 24.21% 降至 15.39%。
- 总碰撞率从约 24.86% 升至 32.23%。
- 超时率从约 8.86% 升至 49.79%。
- episode return 均值从约 7.34 降至 4.92。
- 每 iteration 的 done 数从约 37.15 降至 20.28，说明 episode 整体持续时间明显变长。

### 结论

显式 `out_of_bounds` 惩罚已经解决了主要的高度越界问题，但没有提升整体导航效果。失败模式从高度越界转移为超时和碰撞：策略更少离开高度边界，但大量无人机未能在 35 s 内到达目标，同时静态和动态碰撞比例上升。

成功率在训练后段仍缓慢上升，但 2000 iterations 内的最佳连续窗口也只有约 17.65%，明显低于旧基线。因此下一步不应继续增大越界惩罚，而应重点检查目标推进、成功奖励、超时语义和避障奖励之间的平衡。

### 各运行的含义

#### `ppo_20260818_211713`：将最大时长改为 60 s

此 run 与前一个显式越界惩罚版本使用相同的基本训练规模，但最大 episode 时长从 35 s 改为 60 s。最后 200 个 iteration 中：

- 越界率进一步降至 0.79%，总碰撞率也降至 21.24%。
- 成功率没有改善，只有 14.32%。
- 超时率从 49.79% 升至 63.69%，是主要终止原因。
- 最后 500 个 iteration 的成功率为 14.73%，最后 200 个 iteration 为 14.32%；没有持续上升趋势。
- 最佳连续 50 个 iteration 仅达到 21.51% 成功率，仍有 50.74% 超时。

结论：单纯把时限从 35 s 放宽到 60 s，降低了立即失败的比例，但策略主要选择存活或悬停，没有学会更有效地通过场景。这不是有效的收敛。

#### `ppo_20260818_225534`：奖励函数 V2

此 run 是奖励函数 V2 实验，详细的 term 设计和分项贡献已记录在 `1mdfile/20260818.md`。它的结果明显退化：

- 全程 2,000 个 iteration 的总成功率只有 1.05%，总碰撞率为 82.32%。
- 最后 200 个 iteration 的总碰撞率仍为 82.73%，其中静态碰撞为 66.81%。
- 最后 500 个 iteration 的成功率为 2.13%，最后 200 个 iteration 降至 1.57%；训练后段没有形成改善趋势。
- 最佳连续 50 个 iteration 的成功率也只有 5.71%，同时总碰撞率为 85.25%。
- 加权 episode return 为 -11.58，rollout 单步平均 reward 为 -0.00925。

结论：V2 的实际策略是持续朝目标推进后碰撞。进展信号相对于提前避障的风险信号过强，且风险触发过晚。该版本已撤销是正确的，不应以它作为后续调参基线。

#### `ppo_20260819_222322`：当前最好的导航基线

此 run 恢复为单项 `navigation_reward()` 后取得了目前最好的训练指标：

- 全程成功率为 59.61%，最后 500 个 iteration 为 68.03%，最后 200 个 iteration 为 67.49%。
- 超时率由前 200 个 iteration 的 6.81% 降至最后 200 个 iteration 的 1.87%，说明策略已经具备完成任务的能力。
- 越界率由前 200 个 iteration 的 22.04% 降至 1.72%。
- 总碰撞率由前 200 个 iteration 的 70.91% 降至 28.92%，但仍是后期最主要的失败原因。
- 最佳连续 50 个 iteration 出现在 845--894，成功率为 82.00%、总碰撞率 16.98%、越界率 1.02%、超时率 0%，加权 return 为 +18.16。之后最终稳定在约 67% 至 68%，没有保持该峰值。

结论：该策略已学会基础导航，但还不能称为完成收敛的安全导航策略。后期成功率基本平台化，且约 29% 的已结束 episode 仍然碰撞。应将它作为当前 baseline，先评估多个 checkpoint 的真实泛化表现，再做单变量的避障奖励调整。

### 跨实验结论

训练过程呈现出清晰的失败模式迁移：

1. 初始版本主要通过高度越界结束，越界率为 42.48%。
2. 增加显式越界惩罚后，越界问题被控制到 2% 左右，但失败转为超时和碰撞。
3. 将时限延长到 60 s 没有提高成功率，反而强化了超时行为。
4. V2 奖励把失败模式推向高频碰撞，证明仅使用近距离风险惩罚不足以学习绕障。
5. `ppo_20260819_222322` 同时降低了越界和超时，并显著提高成功率；当前应该聚焦降低碰撞，而不是再次大幅重写全部奖励。

### 可比性限制与下一步

`ppo_20260819_222322` 的训练时间与“起点固定在 `+Y` 边、目标固定在 `-Y` 边、X 坐标均匀排布”的 reset 修改一致，但该修改当时未作为 W&B config 字段记录。W&B 仅保存了 `num_envs`、`physics_dt`、`decimation` 和 `episode_length_s`，没有保存 reset 模式、场景随机种子、障碍配置或奖励版本。因此不能严谨地把该 run 的提升全部归因于奖励函数；任务分布变得更规整也可能是重要因素。

下一轮实验应固定 60 s、固定 reset 模式、固定场景/随机种子，并以 `ppo_20260819_222322` 的 checkpoint 为对照，只修改一类避障信号。每次 run 还应把 `reward_version`、`reset_mode`、静态/动态障碍数量和随机种子写入 W&B config，保证后续结果可以直接比较和复现。
