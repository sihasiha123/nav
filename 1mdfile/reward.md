# 导航奖励函数设计

## 当前情况

`ppo_20260829_203109` 已经收敛，但奖励目标和任务目标没有完全一致：

```text
成功 episode          平均 Return 约 21.8
动态碰撞 episode      平均 Return 约 3.3
静态碰撞 episode      平均 Return 约 0.7
```

失败轨迹仍能因为距离进展和朝目标速度获得正回报。旧版碰撞项虽然写成
`-120`，但 `RewardManager` 会乘以 `step_dt=1/60`，实际只有约 `-2`。

## 调整原则

碰撞惩罚不应调小。应该适度提高“实际进入 Return 的惩罚”，同时控制过程奖励总预算：

```text
过程奖励累计       约 0 ~ +4
安全到达           +4 ~ +6
动态碰撞           -8 ~ -12
静态碰撞           -8 ~ -10
越界               -6 ~ -8
超时               -4 ~ -6
```

代码中的终止值要除以 `step_dt` 反算。例如实际 `-10` 在 `dt=1/60` 时应写成
原始 `-600`。第一轮不要直接使用极大的 `±1200`，先观察成功和失败 Return 是否分离。

## 推荐结构

1. 距离进展：保留，但归一化并裁剪，防止单步异常位移产生大额奖励。
2. 朝目标速度：降低权重；靠近障碍物时衰减，避免高速直冲成为最优策略。
3. 动态避障：危险距离内使用非线性惩罚，重点抑制动态碰撞。
4. 高度、平滑和时间：只作小幅约束，不要主导 Return。
5. 终止项：成功、碰撞、越界、超时只产生一次互斥终止奖励。
6. 成功项：成功立即终止时，只保留一个明确的安全到达奖励，避免重复奖励。

目标不是让总 Return 越高，而是让结果满足：

```text
安全到达 > 接近目标但失败 > 超时 > 越界 > 碰撞
```
